# Tanuki SFNNwoP1536 Output Design

## Goal

Add a dedicated `tanuki-sfnnwop1536` inference-checkpoint format to
`nnue-train`. The generated file must be loadable by the current
`YANEURAOU_ENGINE_NNUE_SFNNwoP1536` configuration in `hakubishin-private`
when the engine and trained network use matching layer dimensions.

The existing `tatara` and `yaneuraou` output formats must remain unchanged.

## Command-Line Contract

Add `tanuki-sfnnwop1536` to `--output-format`.

The format accepts only a plain LayerStack network with all of the following:

- `--feature-set halfka-hm-merged`
- `--bucket-mode progress8kpabs`
- `--num-buckets 8`
- a supplied `--progress-coeff` file
- no PSQT, threat profile, or effect-bucket extension

Layer dimensions are not fixed by the output format. `--ft-out`, `--l1`, and
`--l2` retain the normal LayerStack validation ranges. The consuming engine
must be built with the same dimensions. The current default
`hakubishin-private` binary uses `--ft-out 768 --l1 8 --l2 32`; those values
are used for the end-to-end compatibility test, not enforced by the trainer.

The FT factorizer remains supported because it is a training-only extension
that is folded into the exported inference weights.

## Serialization

Add a `TanukiSfnnwoP1536` internal output-format variant and a dedicated
`save_tanuki_sfnnwop1536` entry point in `nnue-format`.

Refactor the common SFNNWithoutPsqt byte writer behind an internal profile so
the existing YaneuraOu writer and the new Tanuki writer share quantisation,
LEB128 encoding, dense-layer padding, factorizer folding, and row ordering.
Profiles supply only the format-specific values:

| Field | Tanuki value |
|---|---:|
| version | `0x7af32f16` |
| top-level hash | `0x3c203b32` |
| feature-transformer hash | `0x5f134ab8` |
| network hash | `0x6333718a` |
| serialized LayerStacks | 8 |
| architecture text | `Network trained with https://github.com/official-stockfish/nnue-pytorch` |

These values and the architecture text match bullet-shogi's
`tanuki-sfnnwop1536` writer and the current `hakubishin-private` loader. The
architecture text is informational in that loader; shape compatibility is
determined by the engine build and the serialized data.

The existing `save_yaneuraou` entry point remains KingRank9/9-stack only and
continues to emit its current descriptive architecture string.

## Scale and Progress Routing

The Tanuki SFNN file has no field for tatara's `fv_scale`. The generated bytes
therefore do not change when `--fv-scale` changes. The consuming engine's
`FV_SCALE` USI option controls conversion of the raw network output to an
evaluation score.

Training and inference must use the same `progress.bin`. Tatara's
`progress8kpabs` training path uses the same f32 progress computation as
bullet-shogi. The current `hakubishin-private` inference path quantises the
same f64 coefficients to Q16.16, which is existing behavior for networks
trained by bullet-shogi as well.

## Errors

Reject incompatible combinations before allocating the trainer or reading the
full dataset. Error messages must identify the required feature set, bucket
mode, bucket count, progress coefficient, or unsupported model extension.

The Simple architecture must reject `tanuki-sfnnwop1536` with an explicit
LayerStack-only error.

## Verification

Add GPU-independent tests for:

- CLI parsing of `--output-format tanuki-sfnnwop1536`
- valid plain HalfKaHmMerged/progress8kpabs/8-bucket configuration
- rejection of KingRank9, any non-8 bucket count, missing progress
  coefficients, other feature sets, Simple, PSQT, threat, and effect-bucket
- exact Tanuki header constants, architecture text, and eight serialized
  network blocks
- preservation of the existing 9-stack YaneuraOu output
- arbitrary valid LayerStack dimensions in the serializer

Then run a bounded one-superbatch training job with the current engine's
768-8-32 dimensions, place or select the resulting file as `nn.bin`, load the
same `progress.bin`, and confirm the current `hakubishin-private` engine reaches
`readyok` without an NNUE version/hash/read error. Record the engine command and
the required `FV_SCALE` option in the final training instructions.
